2. Сконфигурируйте файловое хранилище:
Выводим список подключенных дисков и их имена.
# lsblk
Обратите внимание какие диски свободны!!!!
[[IMG image33.png]]
в примере sda, adb и adc. На стенде могут отличатся!!!
Устанавливаем утилиту mdadm
#apt-get update && apt-get install mdadm -y
Создание программного RAID 0
Для сборки массива применяем следующую команду:
# mdadm --create --verbose /dev/md0 -l 0 -n 2 /dev/sdb /dev/sdc
[[IMG image34.png]]
Проверяем lsblk
[[IMG image35.png]]
Имя устройства – md0, конфигурация массива размещается в файле /etc/mdadm.conf
#mdadm --detail --scan --verbose | tee -a /etc/mdadm.conf
[[IMG image36.png]]
Монтирование файловой системы массива
Отформатируем разделы в ext4:
# mkfs.ext4 /dev/md0
[[IMG image37.png]]
В корне системы создадим директорию /raid5
#mkdir /raid
разрешми использование папки
#chmod 777 /raid
Монтируем диск для запуска при загрузке системы
[[IMG image38.png]]
Выполним подключение рейда
#mount -t ext4 /dev/md0 /raid
[[IMG image39.png]]
Открываем fstab:
#nano /etc/fstab
И добавляем строку
/dev/md0    /raid0    ext4    defaults    0    0
[[IMG image40.png]]
Выполним подключение рейда
mount -av
RAID массив настроен!
[[IMG image41.png]]
3. Настройте сервер сетевой файловой системы (nfs) на HQ-SRV:
Сервер nfs
Устанавливаем nfs-server
#apt-get install nfs-server -y
Создаем папку общего доступа /raid/nfs
[[IMG image42.png]]
#mkdir /raid0/nfs
Измените права доступа
#chmod 777 /raid0/nfs/
Открываем на редактирование файл /etc/exports который содержит информацию о каталогах, экспортируемых с сервера:
[[IMG image43.png]]
#nano /etc/exports
Создаем шару из каталога /raid/nfs, которая будет доступна для узлов HQ-CLI сети 192.168.0.64/28.Добавим в него строку:
/raid0/nfs       192.168.0.64/28(rw,sync,subtree_check)
[[IMG image44.png]]
Запускаем nfs сервер:
#systemctl enable —now nfs
[[IMG image45.png]]
Выполняем экспорт данных (перечитаем конфигурационный файл /etc/exports, чтобы сервер начал отдавать настроенные шары):
# exportfs -a
Настраиваем автомонтирование на hq-cli.
[[IMG image46.png]]
На HQ-CLI устанавливаем компонент для клиентской части NFS:
#apt-get install nfs-clients
Создаем директорию для автомонтирования /mnt/nfs и добавляем прова
[[IMG image47.png]]
mkdir /mnt/nfs
chmod 777 /mnt/nfs
производим первичное монтирования сетевой папки
[[IMG image48.png]]
#mount -t nfs 192.168.0.1:/raid0/nfs /mnt/nfs
[[IMG image49.png]]
Для автоматического монтирования на HQ-CLI после перезагрузки, используем fstab. Открываем файл fstab:
# nano /etc/fstab
И добавляем строку:
192.168.0.1:/raid/nfs        /mnt/nfs    nfs     auto    0 0
[[IMG image50.png]]
Примонтировать шару:
# mount -av
[[IMG image51.png]]
Проверка
создаем файл в папке  на сервере с hq-cli
#touch /mnt/nfs/test
проверяем на сервере
[[IMG image52.png]]
#ls /raid0/nfs
[[IMG image53.png]]
Сервер настроен!

5. Сконфигурируйте ansible на сервере BR-SRV
Создание пары SSH-ключей.
Чтобы заходить на удаленные машины, пользователь на BR-SRV (sshuser и root) должен создать пару из закрытого/открытого RSA ключа. Это делается следующей командой:
# ssh-keygen -t rsa
Далее Enter
Данную операцию оптимально проделать и от root  «sudo ssh-keygen -t rsa».
[[IMG image61.png]]
В результате в каталоге /home/sshuser/.ssh или /root/.ssh будут созданы файлы ключей:
ls -l ~/.ssh
id_rsa  # закрытый ключ
id_rsa.pub # открытый ключ
[[IMG image62.png]]
[[IMG image63.png]]
Копируем открытый SSH-ключ на удаленные устройства под пользователем sshuser:
Копируем ключ для пользователя sshuser на HQ-SRVНа HQ-SRV ssh порт изменен, указываем его
ssh-copy-id -p 2024 sshuser@192.168.0.1
[[IMG image64.png]]

#systemctl status sshd
[[IMG image65.png]]
Копируем ключ
#ssh-copy-id user@192.168.0.65
[[IMG image66.png]]
По аналогии проделываем для пользователя root.
Устанавливаем ansible.
apt-get update
apt-get install ansible -y
[[IMG image67.png]]
Подготовка файла инвентаря (hosts) на BR-SRV/
Редактируем файл инвентаря /etc/ansible/hosts
#sudo nano /etc/ansible/hosts
[[IMG image68.png]]
Сначала указывается название группы в квадратных скобках, затем перечисляются хосты с параметрами: ip, порт (если изменен со стандартного), имя пользователя.[HQ]

hq-rtr ansible_host=192.168.0.62 ansible_user=net_admin
hq-cli ansible_host=192.168.0.65 ansible_user=user
