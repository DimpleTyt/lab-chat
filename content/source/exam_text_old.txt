2. Сконфигурируйте файловое хранилище:
Выводим список подключенных дисков и их имена.
# lsblk
Обратите внимание какие диски свободны!!!!
в примере sda, adb и adc. На стенде могут отличатся!!!
Устанавливаем утилиту mdadm
#apt-get update && apt-get install mdadm -y
Создание программного RAID 0
Для сборки массива применяем следующую команду:
# mdadm --create --verbose /dev/md0 -l 0 -n 2 /dev/sdb /dev/sdc

Проверяем lsblk

Имя устройства – md0, конфигурация массива размещается в файле /etc/mdadm.conf
#mdadm --detail --scan --verbose | tee -a /etc/mdadm.conf 

Монтирование файловой системы массива
Отформатируем разделы в ext4:
# mkfs.ext4 /dev/md0

В корне системы создадим директорию /raid5
#mkdir /raid
разрешми использование папки
#chmod 777 /raid
Монтируем диск для запуска при загрузке системы
Выполним подключение рейда
#mount -t ext4 /dev/md0 /raid

Открываем fstab:
#nano /etc/fstab
И добавляем строку
/dev/md0    /raid0    ext4    defaults    0    0

Выполним подключение рейда
mount -av
RAID массив настроен!

3. Настройте сервер сетевой файловой системы (nfs) на HQ-SRV:
Сервер nfs
Устанавливаем nfs-server
#apt-get install nfs-server -y
 Создаем папку общего доступа /raid/nfs
#mkdir /raid0/nfs
Измените права доступа
#chmod 777 /raid0/nfs/
Открываем на редактирование файл /etc/exports который содержит информацию о каталогах, экспортируемых с сервера:
#nano /etc/exports
Создаем шару из каталога /raid/nfs, которая будет доступна для узлов HQ-CLI сети 192.168.0.64/28.Добавим в него строку:
 /raid0/nfs       192.168.0.64/28(rw,sync,subtree_check)

Запускаем nfs сервер:
#systemctl enable —now nfs

Выполняем экспорт данных (перечитаем конфигурационный файл /etc/exports, чтобы сервер начал отдавать настроенные шары):
# exportfs -a
Настраиваем автомонтирование на hq-cli.
На HQ-CLI устанавливаем компонент для клиентской части NFS:
#apt-get install nfs-clients
Создаем директорию для автомонтирования /mnt/nfs и добавляем прова
 mkdir /mnt/nfs
chmod 777 /mnt/nfs
производим первичное монтирования сетевой папки
#mount -t nfs 192.168.0.1:/raid0/nfs /mnt/nfs

Для автоматического монтирования на HQ-CLI после перезагрузки, используем fstab. Открываем файл fstab:
# nano /etc/fstab
И добавляем строку:
192.168.0.1:/raid/nfs        /mnt/nfs    nfs     auto    0 0

Примонтировать шару:
# mount -av

Проверка
создаем файл в папке  на сервере с hq-cli
#touch /mnt/nfs/test
проверяем на сервере
#ls /raid0/nfs 

Сервер настроен!
4. Настройте синхронизацию времени между сетевыми устройствами по протоколу NTP на ISP

Заходим в конфигурационный файл "chrony.conf" на ISP
nano /etc/chrony.conf – ввод (Enter)

Приводим конфигурационный файл к следующему виду (рис. 3.2) IP-адреса согласно вашим параметрам:
allow 172.16.4.0/28
allow 172.16.5.0/28
local stratum 5

Сохраняем файл и выходим.
Перезапускаем службу синхронизации
systemctl restart chronyd – ввод (Enter)

Настройка NTP клиентов  на примере hq-srv, br-srv, hq-cli.
Заходим в конфигурационный файл "chrony.conf"
nano /etc/chrony.conf – ввод (Enter)
Приводим конфигурационный файл к следующему виду IP-адреса согласно вашим параметрам, пункт pool 2.ru.pool.ntp.org iburst закомментировать или удалить!:
server 172.16.1.14 iburst prefer

Сохраняем файл и выходим.
Запускаем службу синхронизации
systemctl restart chronyd – ввод (Enter)

Проверяем 
chronyc sources – ввод (Enter)

Остальные устройства (HQ-CLI и BR-SRV) настраиваем по аналогии с HQ-SRV.

5. Сконфигурируйте ansible на сервере BR-SRV

Создание пары SSH-ключей.
Чтобы заходить на удаленные машины, пользователь на BR-SRV (sshuser и root) должен создать пару из закрытого/открытого RSA ключа. Это делается следующей командой:
# ssh-keygen -t rsa
Далее Enter
Данную операцию оптимально проделать и от root  «sudo ssh-keygen -t rsa».

В результате в каталоге /home/sshuser/.ssh или /root/.ssh будут созданы файлы ключей:
ls -l ~/.ssh
id_rsa  # закрытый ключ
id_rsa.pub # открытый ключ

Копируем открытый SSH-ключ на удаленные устройства под пользователем sshuser:
Копируем ключ для пользователя sshuser на HQ-SRVНа HQ-SRV ssh порт изменен, указываем его
ssh-copy-id -p 2024 sshuser@192.168.0.1

проверяем работает или нет на HQ-CLI службу SSH и копируем ключ на HQ-CLI
#systemctl status sshd

Копируем ключ
#ssh-copy-id user@192.168.0.65

По аналогии проделываем для пользователя root.
Устанавливаем ansible.
apt-get update
apt-get install ansible -y

Подготовка файла инвентаря (hosts) на BR-SRV/
Редактируем файл инвентаря /etc/ansible/hosts
#sudo nano /etc/ansible/hosts

Сначала указывается название группы в квадратных скобках, затем перечисляются хосты с параметрами: ip, порт (если изменен со стандартного), имя пользователя.[HQ]
hq-srv ansible_host=192.168.0.1 ansible_port=2026 ansible_user=sshuser
hq-rtr ansible_host=192.168.0.62 ansible_user=net_admin
hq-cli ansible_host=192.168.0.65 ansible_user=user
[BR]
br-rtr ansible_host=192.168.1.30 ansible_user=net_admin
Проверка настройки Ansible
ansible all -i -m ping

Может появиться предупреждение про обнаружение интерпретатора Python, на целевом хосте

Для управления поведением обнаружения в глобальном масштабе необходимо в файле конфигурации ansible /etc/ansible/ansible.cfg в разделе [defaults] прописать ключ interpreter_python с параметром auto_silent. В большинстве дистрибутивов прописываем вручную.
# nano /etc/ansible/ansible.cfg
Прописываем вручную
Проверяем
Инвентарь настроен
6. Развертывание приложений в Docker на сервере BR-SRV.
Устанавливаем docker и docker-compose
#apt-get update
#apt-get install docker docker-compose -y
Запуск docker
#systemctl enable docker —now

Загружаем образ в среду виртуализации и монтируем на виртуальную машину ISO образ.
В системе виртуализации выбираем local дальше ISO-образы и Отправить.
  
Находим образ и добавляем его в систему
Выбрать файл

Рабочий стол > приложение > Additional.iso > открыть

На устройства подключаем диск, выбираем устройство, заходим в оборудование, двойным кликом открываем меню CD/DVD

Выбираем образ: использовать образ файла, выбираем хранилище local, выбираем ISO-образ, нажимаем ОК

Проверяем имя устройства CD на виртуальной машине
lsblk

монтируем Additional.iso образ
mount  /dev/sr0 /mnt/

Проверяем файлы для настройки docker в образе Additional.iso
ls /mnt/docker/
импортируем в docker установочные файлы с Additional.iso
docker load < /mnt/docker/mariadb_latest.tar
docker load < /mnt/docker/site_latest.tar
  
Копируем compose.yaml в корневую директорию
# sudo cp /mnt/compose.yaml .
Запускаем контейнеры docker-compose
#docker compose -f web.yaml up -d  

Приложение должно быть доступно для внешних подключений через порт 8080
