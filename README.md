# lab-chat

Чат-инструктор по лабораторной работе. Пользователь вставляет своё задание,
DeepSeek собирает под него план шагов и ведёт по нему: одна команда или одно
действие в интерфейсе за раз. На вопрос или ошибку отвечает коротко, без
забегания вперёд.

**Сайт:** https://exam.nothing-box.com

**CLI (сеть нужна):**

```bash
curl -o labchat.py https://exam.nothing-box.com/download/labchat.py
python3 labchat.py
```

**CLI офлайн (сеть не нужна):**
[labchat-offline.py](https://exam.nothing-box.com/download/labchat-offline.py) ·
33 КБ · один файл · только стандартная библиотека Python

```bash
curl -o labchat-offline.py https://exam.nothing-box.com/download/labchat-offline.py
python3 labchat-offline.py
```

Если стенд изолирован, скачай файл заранее и перенеси на флешке.

## Как это работает

```
текст задания
     │
     ▼
variant.json          домен, IP, RAID, диски, монтирование, NFS, NTP, порт
     │                (детерминированный парсер + дозаполнение моделью)
     ▼
карточка подтверждения  «ИЗ ЗАДАНИЯ» / «ИЗ МЕТОДИЧКИ», поля редактируются
     │
     ▼
компилятор плана     шаблоны шагов × параметры варианта → 84 шага
     │
     ▼
чат                 шаг, «Дальше», откат по номеру, вопросы
```

Ключевое решение: **шаги хранит сервер, а не модель**. Модель не пересказывает
методичку и не считает шаги, она только разбирает задание, отвечает на вопросы
и разбирает ошибки. Поэтому на 60-м шаге не начинает выдумывать команды.

Варианты отличаются в основном уровнем RAID, и это учитывается в командах:

| RAID | Дисков | Команда |
|---|---|---|
| 0 | 2 | `mdadm --create --verbose /dev/md0 -l 0 -n 2 /dev/sdb /dev/sdc` |
| 1 | 2 | `mdadm --create --verbose /dev/md0 -l 1 -n 2 /dev/sdb /dev/sdc` |
| 5 | 3 | `mdadm --create --verbose /dev/md0 -l 5 -n 3 /dev/sdb /dev/sdc /dev/sdd` |
| 10 | 4 | `mdadm --create --verbose /dev/md0 -l 10 -n 4 /dev/sdb /dev/sdc /dev/sdd /dev/sde` |

Пути (`/raidN`, `/raidN/nfs`), имена хостов и порты тоже подставляются из
варианта. Изменение RAID в карточке пересобирает план целиком.

## Команды CLI

```
Enter        следующий шаг
текст        вопрос или описание ошибки
/step N      перейти к шагу N (или к id вида 2.3)
/restart     начать заново
/variant     изменить задание
/repeat      повторить текущий шаг
/copy        показать команду текущего шага отдельно
/hint        подсказка (офлайн-версия)
/quit        закрыть программу
```

Офлайн-версия не ходит в сеть: шаги и разбор ошибок берутся из методички,
ответов модели нет.

## Сервер

FastAPI + SQLite, фронтенд без сборки, Caddy с автоматическим HTTPS.

```bash
sudo bash deploy/install.sh /path/to/lab-chat
nano /opt/lab-chat/.env          # DEEPSEEK_API_KEY, MODEL_MAIN
python tools/create_user.py roma
```

Подробности: [docs/RUNBOOK.md](docs/RUNBOOK.md), три способа публикации:
[deploy/README.md](deploy/README.md).

### Аккаунты

Регистрации нет, пользователей заводит администратор скриптом
`tools/create_user.py`. Пароли хранятся как scrypt-хеши.

Сессия: 1 час без действий, каждое действие продлевает. Cookie `Secure`,
`HttpOnly`, сервер проверяет срок сам.

## Структура

| Путь | Что |
|---|---|
| `app/` | backend: auth, API, SSE, разбор задания, LLM |
| `web/` | интерфейс: чёрная тема, моно, без сборки |
| `content/modules/` | шаблоны шагов, 8 модулей |
| `content/source/` | исходная методичка и извлечённый текст |
| `cli/` | терминальный клиент и офлайн-сборка |
| `shared/` | модель варианта, компилятор, рендер шага |
| `tools/` | проверки, сборка офлайна, создание пользователей |
| `deploy/` | systemd, Caddy, установка |

## Разработка

```bash
python -m pip install -r requirements.txt
python tools/validate_modules.py     # шаблоны + сборка для RAID 0/1/5/10
python tools/smoke.py                # API-прогон без ключа модели
python tools/build_offline.py        # пересобрать офлайн-клиент
cp .env.example .env                 # без ключа работает mock-режим
uvicorn app.main:app --port 8000
```

`tools/check_deepseek.py` проверяет ключ и печатает доступные id моделей.

## Ограничения

- Команды сверены с методичкой, но на живом стенде Astra проверялись не все.
- Модуль 1 сжат до 12 шагов: часть действий (`su`, `sudo id`,
  `samba-tool ... show`) в него не вошла.
- Строка `/etc/sudoers.d/hq` восстановлена по скриншоту, в тексте методички её нет.
- DeepSeek V4 по умолчанию «думает» и тратит на это лимит токенов, поэтому
  размышления отключены параметром `thinking`, а `THINKING=1` включает обратно.
